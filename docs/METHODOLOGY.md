# MT-PhishingBench — Dataset Construction Methodology

> Construction methodology for the Korean voice-phishing **multi-turn dialogue benchmark**.
> Working draft for the paper's *Dataset Construction* section. Citations prioritize
> internationally recognized venues; domestic sources are used only where no substitute exists.
>
> The dataset described in this document is used in the paper "Beyond Detection Task: A
> Turn-Level Benchmark for Fraud Scenario-Aware Understanding and Timely Intervention in
> Financial Live Chat Phishing Conversations" (submitted to ICAIF '26, currently under
> anonymous review). The model used to generate positive dialogues is **Claude Opus 4.8**
> (multi-agent roleplay); the labeling/verification model is **Claude Sonnet 5**.

---

## 1. Overview and Contributions

Existing Korean voice-phishing resources (KorCCVi: 2,927 real transcripts, single-utterance
labels, binary classification) and international fraud-detection datasets (TeleAntiFraud-28k:
Chinese, audio) fail to simultaneously provide **multi-turn dialogue structure, fine-grained
type labels, victim personas, and a defense-evaluation protocol**.

MT-PhishingBench aims to be the **first Korean benchmark** that simultaneously satisfies:

1. **Multi-turn**: long-form dialogue between a persistent attacker and a victim who reacts in
   stages (resistance → persuasion → compliance/refusal)
2. **Three-axis labeling**: fraud type (T1–T9) × progression stage × persuasion technique,
   attached at the utterance level
3. **Persona control**: victim diversity with statistically controlled demographic
   representativeness
4. **Multi-task**: supports detection, type classification, stage/technique sequencing, and
   defensive-intervention evaluation
5. **Dual grounding**: synthesis anchored at both ends to real phishing calls (FSS) and real
   normal calls (AIHub)

### 1.1 Differentiation from Prior Work
| Resource | Language/modality | Structure | Type labels | Persona | Defense evaluation |
|---|---|---|---|---|---|
| KorCCVi v1/v2 | Korean/text | **single utterance** | binary (phishing/normal) | none | none |
| TeleAntiFraud-28k | Chinese/audio+text | multi-turn | 7 types | none | none |
| LLM-attack research (ViKing, etc.) | English/audio | multi-turn | — | partial | (attack perspective) |
| **MT-PhishingBench** | **Korean/text** | **multi-turn (persistent)** | **T1–T9 multi-label** | **Nemotron-controlled** | **intervention-timing evaluation** |

### 1.1b Broader Related-Work Landscape (reflecting paper §2)

The table above covers only direct Korean voice-phishing comparators. The paper argues its
distinctiveness against three broader lines of prior work as well (§2.1–2.4); this document
summarizes them. See [docs/REFERENCES_en.md](REFERENCES_en.md) §G for full citations.

| Line of work | Representative resources | Difference from this benchmark |
|---|---|---|
| Finance-specific benchmarks | ConvFinQA, FinBen, FSKU, FinRED | Treat financial text as fixed evidence; do not model conversational fraud or turn-level decisions |
| Multi-turn scam/safety benchmarks | Fraud-R1 (5 inducement categories), PreScam (11,573 kill-chain-labeled reports) | Missing some or all of the online-prefix protocol, hierarchical typing, and intervention-timing evaluation |
| Scam-progression frameworks | ScriptMind (571 Korean voice-phishing cases, crime-script supervision) | A training framework rather than a benchmark; no standardized answer key or hierarchical scoring |
| Defensive simulation systems | SE-VSim/SE-OmniGuard, scambaiting systems (Puppeteer, etc.) | Evaluated only on their own simulated data; no standardized prefix protocol |

None of these three lines jointly evaluates "detection, hierarchical fraud type,
utterance-level dynamics, and intervention timing at every observed prefix" — this combination
is the paper's core differentiation argument.

### 1.2 The Dual Composition of the negative (normal) Class
The negative class consists of **two independent subsets** differing in source and the team
that built them.

| Subset | Raw source | How real data is used | Built by |
|---|---|---|---|
| **(a) Everyday-conversation** | AIHub 012/020 SNS multi-turn dialogue data (topic, register) | **Seed**: only the topic/scene trigger is extracted; the dialogue lines and structure are newly generated by an LLM / **Grounding**: Nemotron personas (demographic fields used as-is) | Newly built by this research team (details in §2.2, §3.4–3.6, §4.2, §6.2, §7.2, §8.2) |
| **(b) Consultation-call** | AIHub call-center/consultation data | **Grounding**: the real data itself | Pre-built independently by a separate team member (`normal_conversations.json`) |

The pre-existing negative class was grounded only in subset (b), i.e., **institution-to-customer
business calls**, which meant there was no hard-negative anchor at all corresponding to T4
(family/acquaintance impersonation) — **personal, interpersonal call scams** such as "my phone
broke, I need money urgently." Subset (a) was newly built to close this gap of missing hard
contrastive examples that share the same surface story but differ in structure. Elsewhere in
this document, unqualified references to "negative" denote (a); the construction principles,
theoretical grounding, and QC methods for (b) may differ from what is described here.

## 2. Design Principles

### 2.1 positive (fraud)

| Principle | Description | Effect |
|---|---|---|
| **Controlled generation** | Every dialogue is sampled from a deterministic cell of the *design matrix* (no free generation) | Guarantees coverage and label balance across type, difficulty, and outcome |
| **Dual grounding** | Input = real FSS phishing anchors; normal class = real AIHub data (see §1.2 — this applies only to negative subset (b)) | Structurally forecloses "synthetic ≠ real distribution" concerns |
| **Generation/annotation separation** | The model that writes the dialogue is separate from the model that labels it | Prevents label self-justification and leakage |
| **Meta-awareness blocking** | The victim agent is never told it is in a "phishing scenario" | Prevents unrealistic immediate refusal; reproduces natural victimization |
| **Outcome control** | Success/attempt-failed/terminated-early are *deliberately* mixed and labeled (success 781 · terminated early 638 · attempt failed 581) | Refusals are also valid data; false-positive evaluation becomes possible |

### 2.2 negative (normal, everyday-conversation)

| Principle | Description | Effect |
|---|---|---|
| **CA structural control** | Calls are generated in the order (identification) → greeting → small talk → topic → closing, with identification conditional (only stated explicitly for unfamiliar numbers) | Prevents script-like uniformity; reproduces the diversity of real call openings |
| **T4 symmetric hard negatives** | For each T4 subtype (7 call-channel types), designs contrastive pairs that keep the surface story but differ in structure | Forces fraud detectors to rely on structure, not surface keywords |
| **Minimal-intrusion masking** | Because personas are synthetic (not real personal data), name/contact masking (●) was deliberately not applied after principled review (only some fields, e.g. addresses, are selectively masked) | Trades full formal alignment with call-center data conventions for generation efficiency and naturalness |
| **Mandatory signal verification** | Code-verified whether `required_ca_signals` are actually tagged on the correct turn's `psych_technique`, retrying (up to 3 times) if not | Structurally guarantees required signals (e.g., identity-verification responses) that prompt instructions alone failed to enforce *(however, `psych_technique` in the final release is almost entirely empty arrays — the signal is lost as tagging metadata, though the content the signal was meant to convey appears to be reflected in the turn text itself)* |
| **Chunked, resumable generation** | Generation is split into batches of 250, automatically skipping already-completed IDs | Safely runs large-scale API calls in chunks, tracking tokens/cost |

## 3. Theoretical Foundations (Three Axes)

Dialogues are decomposed along **three axes**, each grounded in a distinct body of literature.

### 3.1 Type Ontology — T1–T9 (Official Financial-Authority Classification)
*Who* the attacker impersonates and *what* they are after. Composed of 9 top-level categories
(institution impersonation / financial-institution impersonation / loan fraud /
family-acquaintance impersonation / investment fraud / e-finance fraud / general fraud /
illegal finance / money laundering) with up to 4 levels of sub-classification. This taxonomy is
not a citation but is presented as a **contribution of the research team (FSI)**.

> Structural observation: the T-classification is not a single axis but a mixture of
> **(A) impersonated identity/scenario goal** (T1–T5, T7), **(B) modus operandi** (T6 malicious
> apps/smishing, T8 mule accounts), and **(C) money flow** (T9). Labels are therefore designed
> as **multi-label**, and T9 (money laundering) — which reflects money flow rather than the
> conversation itself — is handled as an **overlay label** (plus a separate sub-corpus of
> recruitment dialogues) (§4).

### 3.2 Progression Script — Crime Script Analysis
*How* the call unfolds. Applies **Cornish's (1994)** crime script analysis to decompose the
call into scenes: `contact → trust-building/deception (deception) → compliance-inducing
(compliance) → extraction`. Victim compliance dynamics are reinforced with **Whitty's (2013)**
scam compliance model. (Choi & Kim (2015) may be cited as a supporting reference for a Korean
application case.)

### 3.3 Persuasion Tactics — Social-Engineering Persuasion Principles
*How* each utterance manipulates. Uses a coding scheme integrating three established
frameworks:
- **Cialdini's** six principles of influence (reciprocity, consistency, social proof,
  authority, liking, scarcity)
- **Stajano & Wilson (2011, CACM)** seven principles of scams (distraction, social compliance,
  herd, dishonesty, kindness, need and greed, time)
- **Ferreira et al. (2015, Springer)** integrated five principles (authority, social proof,
  liking/similarity/deception, consistency/reciprocity, distraction)

→ Utterance labels use **Ferreira's five principles as the base**, with Korea-specific
extended tactics (isolating the family, invoking "non-face-to-face investigation," fear
induction) tagged on top.

### 3.4 negative (normal) Theoretical Foundation — Call-Opening Structure

Just as the positive side is anchored in Crime Script (Cornish), the negative
(normal, everyday-conversation) side is anchored in call-opening structure and speech-act
theory.

**Call-opening structure — Schegloff's telephone-call research**: Schegloff (1968, 1986)
showed that telephone calls follow a formalized opening sequence of
`identification/recognition → greeting → small talk → topic transition → closing`. Reflecting
the tendency for caller identification/recognition to be **omitted or diversified** in modern
smartphone environments where the caller's number is already exposed, we required explicit
identification only for hard-negative scenarios (T4 scenarios with an unfamiliar number), and
used varied opening patterns (e.g., "oh, what's up?") elsewhere. This design intent is reflected
in the actual release data — casual calls between coworkers skip identification and go straight
into greetings, while family/friend scenarios with a changed number contain an explicit
identity-verification sequence ("what was your childhood nickname?") as a separate turn.

### 3.5 negative (normal) Theoretical Foundation — Conversation Speech-Act/Function Classification

- **Sacks, Schegloff & Jefferson (1974)**: turn-taking, adjacency pairs, repair — the
  theoretical basis for the structural criteria (filler phrases, backchannel questions,
  reaction-token frequency) distinguishing natural conversation from script-like dialogue.
- **Goldsmith (1996)**: a taxonomy of 29 speech events occurring in everyday relationship
  formation — the basis for the request/sharing/relationship-maintenance three-way
  classification.
- **Jumanto (2017)**: a 12-function classification of phatic communication, used to identify
  the raw material for topical diversity in the text (SNS) seed corpus.
- **Brown & Yule (1983)**: the interactional vs. transactional distinction in language
  function — the basis for reflecting channel characteristics (calls skewing transactional,
  text skewing phatic).
- **Media Richness Theory (Daft & Lengel, 1986)**: the relationship between medium choice and
  message importance — the theoretical basis for the decision to regenerate topic seeds into
  call structure rather than substituting the original text verbatim.

### 3.6 negative (normal) Theoretical Foundation — Persuasion/Normalcy Signals (Inverting the positive Theory)

The Cialdini, Stajano-Wilson, and Ferreira persuasion principles used on the positive side were
**inverted** and converted into conditions for hard-negative slots — "this persuasion principle
must be absent or appear in reverse" (`required_ca_signals`: identity-verification-response,
channel-switch-acceptance, low-pressure-intensity, familiar-account, buffer-interval-present).
However, these signals are not explicitly retained as tags in the final data. In contrast, the
**content** the signals were meant to convey (re-confirming an account, accepting a video call,
buffering phrases like "it's not urgent") is actually observed within the turn text — i.e., the
signal was lost as tagging metadata but appears to be reflected in the generated content.

## 5. Real-Data Grounding

| Role | Source | Notes |
|---|---|---|
| Phishing anchor (register, progression, length) | **FSS "This is the Voice"**: 101 reported posts → 180 recovered calls → 170 usable transcripts | STT (mlx-whisper) + human correction. Videos are not redistributed; only transcript text is used. Under the paper's evaluation-snapshot rule (excluding ≤3-turn conversations), 141 are reflected |
| negative (a) everyday-conversation — topic/register **seed** | **AIHub 012. Korean SNS multi-turn dialogue data**, **020. everyday text dialogue data by topic** | The original text is not substituted directly — only the topic is used as a seed; a first-pass rule filter followed by a 1.5-stage heuristic scoring selects 300 items per topic (8,700 total). The original dialogue text itself does not appear in the output |
| negative (a) everyday-conversation — persona **grounding** | **nvidia/Nemotron-Personas-Korea** | Extracted and reduced demographic fields only from the 7.6GB original (547MB → a 3,000-person stratified sample), with age/gender constraints applied per relationship type. Age, gender, occupation, and region fields remain in the record as-is |
| negative (a) everyday-conversation — T4-matching scene **seed** | Records with T4.1.x/T4.2.x (channel=call) from **MT-PhishingBench.jsonl** | Only the triggering situation of the fraud scenario is referenced; names/details are rewritten |
| negative (b) consultation-call class | **AIHub call-center/consultation data** | Real-data grounding. Pre-built independently by a separate team member (§1.2). Copyright cleared; rich in financial vocabulary (suitable as an adversarial negative) |
| (optional) additional phishing vocabulary | 695 KorCCVi phishing examples | Used to supplement when readily accessible |

Real-measured distributions of **turn length, per-stage time-on-task, and expression
patterns** are extracted from the FSS transcripts and used as synthesis parameters.
Specifically, the median turn count, an **attacker:victim utterance-length ratio ≈7:1**, and
the **persuasion-signal frequency ordering (isolation > urgency > fear > authority)** are
reflected as target statistics during synthesis. External resources are adopted only when
they satisfy all of ① a license permitting redistribution/derivative use, ② multi-turn
structure, and ③ fidelity to Korean context (translated imports are avoided, since
translationese undermines realism).

> **Seed vs. grounding distinction**: "Seed" refers to cases where only a fragment of real
> data (a topic label, a scene trigger, etc.) is drawn as a starting point for generation while
> the dialogue lines, structure, and detail are newly created by the LLM (the 012/020 SNS
> corpora and the MT-PhishingBench T4 hints in the table above); "grounding" refers to cases
> where real-data field values remain in the output directly (or nearly so) (Nemotron personas,
> AIHub call-center real data). Within negative (a), only the persona can properly be called
> "grounding."

## 6. Personas (Dual Design)

### 6.1 positive (fraud)

| | Victim persona (demographic) | Attacker persona (operational) |
|---|---|---|
| Source | **nvidia/Nemotron-Personas-Korea** | Constructed from T-codes |
| Composition | Age, gender, region, occupation, education, household, personality + **vulnerability factors** (financial literacy, digital literacy, suspicion tendency 0–1, psychological state) | **Impersonated identity** (T-code → concrete identity) · **organizational role** · **skill level** · **script familiarity** · **register** · **rebuttal repertoire** |
| Sample stratification | **5 vulnerability groups** (older adults, middle-aged adults, young workers, the self-employed, homemakers/unemployed) × **150 each** = 750, each persona supplying demographic attributes + a narrative profile | — |
| Responsible for | Response diversity, representativeness | Modus-operandi coverage, persistence |
| Sampling | **Stratified** by vulnerability group | Per the design matrix |

### 6.2 negative (normal, everyday-conversation)

| | Caller (caller_persona) | Recipient (victim_persona) |
|---|---|---|
| Source | Nemotron stratified sample (3,000 people) | Matched from the same pool subject to relationship constraints |
| Relationship constraints | Per-relationship-type functions (`match_child`, `match_son`, `match_younger_sibling`, `match_friend`, `match_coworker`, `match_junior_schoolmate`) | Age gap, employment status, **gender** conditions (son enforced as male, initially missing then corrected) |
| Known limitation | Relationship types other than "son" (e.g., younger sibling) have no gender constraint applied | |

Both subsets share the same demographic persona pool, **nvidia/Nemotron-Personas-Korea**, but
positive includes vulnerability factors (susceptibility, etc.) as persona fields, while
negative (a) assigns susceptibility separately at generation time rather than fixing it in the
persona (connected to the QC observations in §8).

## 7. Generation Pipeline

### 7.1 positive (fraud)

```
REAL ANCHORS:  IN= 101 FSS transcripts       NEG= AIHub normal calls
      │ grounding                                 │
      ▼                                            ▼
[A] Knowledge base: T1–T9 ontology · persuasion-technique definitions · FSS register/length statistics · Nemotron
      ▼
[B] Design-matrix sampler: T-code × persona group × outcome × difficulty   (stratified, controlled)
      ▼
[C] Scenario scaffolder: scene sequence (contact→deception→compliance→extraction) + role set + props
      ▼
[D] Multi-agent roleplay (generation model: Claude Opus 4.8): attacker / victim / orchestrator
      │   - attacker = domain-knowledge prompting (§7.1.1 below), persistence·rebuttal
      │   - victim = persona-conditioned, ★unaware it is phishing (meta-awareness blocking)
      │   - orchestrator = scene transitions, suspicion injection, outcome control
      ▼                       ▲ N rounds of feedback
[D'] CRITIC (mixture of expert LLMs, Jandaghi 2024): scores persona fidelity, persistence, label consistency
      ▼ (converged batch)
[E] Labeler pass (model: Claude Sonnet 5, separate from the generation model): per-utterance stage · technique · T-code · intervention_point + conversation label · <think>
      ▼
[F] Quality gate: automated (schema · duplicate Self-BLEU/distinct-n · real-name blocking) → human review (Fleiss' κ)
      ▼
[G] Release: JSONL + Datasheet (Gebru 2021) + ethics/intended-use documentation
```

#### 7.1.1 Domain-Knowledge Prompting (Attacker Agent)
Injects domain knowledge instead of generic CoT (Sim & Kim 2025: domain-knowledge prompting >
CoT).
```
[Identity]  {T-code} → concrete identity (e.g., T1.1.1 → Investigator [Name], Seoul Central District Prosecutors' Office)
[Goal]      Extraction method = {transfer|in-person|gift cards|app installation|open banking}, amount
[Scene]     {contact|deception|compliance|extraction}
[Tactic]    The persuasion principle for this scene (Ferreira) + example phrasing
[Method]    {T-code} modus-operandi definition + props (forged documents, spoofed numbers)
[Register]  Expression anchors extracted from real FSS transcripts
[Rebuttal]  Response by victim-suspicion type (isolation/re-authorization/confidentiality/urgency escalation) ← "use any means necessary"
[Rule]      Persist until the goal is met. No character breaking, no self-referential AI mentions
```

#### 7.1.2 Meta-Awareness Blocking (Victim Agent)
Given only a persona plus the *ordinary situation* of "an unknown number called." The ground-truth
label is withheld. Natural resistance/compliance follows from the suspicion tendency → refusal
is also a valid outcome (outcome = terminated_early).

### 7.2 negative (normal, everyday-conversation)

```
SEED: 012/020 SNS (topic, register)   MT-PhishingBench.jsonl (T4 scene seed)   GROUNDING: Nemotron (persona)
      │                                        │                                │
      ▼                                        ▼                                ▼
[A] Knowledge base: first-pass rule filter → 1.5-stage heuristic pre-scoring (CA-axis approximation) → 300 per topic (8,700 total)
      ▼
[B] Design-matrix sampler: Track B (T4 matching, 7 relationships × 3 intensities = 21 cells) + Track A (general topics, 29 topics)
    → 1,000 slots total, relationship-constrained persona pairs assigned, register/scene seeds linked
      ▼
[C] Scenario scaffold: CA opening structure + masking rules + required_ca_signals mapping rules (single source of truth document)
      ▼
[D] Generation (Claude Sonnet 5 API): prompt construction (including persona pre-masking)
      → validation (format, speaker labels, signal tagging) → up to 3 retries on failure
      → executed in 250-item chunks, with real-time token/cost tracking
      ▼
[E] QC review: masking omissions, naturalness, call-likeness (residual chat-register artifacts) — 3 axes (LLM review + rule-based pre-scan)
      ▼
Release: JSONL + wrapper compatible with normal_conversations.json
```

The largest methodological difference from the positive pipeline's [D] multi-agent roleplay +
iterative CRITIC structure is that negative (a) is generated via a **single call** (Claude
Sonnet 5, structured prompt).

#### 7.2.1 QC Review — Actual Implementation and Design Lessons

QC consists of the following three axes.

1. **Structural/rhythmic naturalness** — consistency of address terms, small-talk-to-topic
   transition markers, diversity of reaction tokens, buffer phrases/self-repair, redundant
   repetition
2. **Referential consistency** — errors where a speaker refers to information (a name, a
   place, etc.) not previously provided in an earlier turn as if it were already known. *This
   axis was not specified in the original design document; it was newly identified during
   actual data review* (e.g., the recipient responding with the exact correct name even though
   the caller never stated it).
3. **Content/strategy-axis preservation** — content that provides the basis for label
   discrimination (account requests, mentions of money, pressure language, etc.) is explicitly
   protected from being mistaken for a style issue and deleted. However, excessive
   pre-emptive evidence offers not prompted by the other party (e.g., unprompted offers of a
   video call or a receipt) are handled separately as a mitigation target.

A small number of pure generation artifacts (e.g., a speaker-label string literally appearing
inside a turn's `text` field) were also identified; instructions were added to fix such
"obvious errors" with top priority, separately from the three axes above.

**Prompt design: checklist-first → open-ended narration-first**

Initially, the system prompt presented the three axes above as a numbered checklist and asked
for JSON output immediately. This approach, however, tended to miss defect types not covered by
the checklist (e.g., simple generation bugs like speaker-label leakage). Instead, letting the
reviewer freely note anything that felt off — as a human would on a first read — and reordering
the prompt so that **free-form narration explaining the reasoning precedes the JSON output**
was found to improve defect-detection quality (at the cost of somewhat higher output-token
usage and therefore cost, due to the added free-form narration).

## 8. Quality Assurance and Metrics

### 8.1 positive (fraud)

| Dimension | Method |
|---|---|
| Diversity | **Self-BLEU**, **distinct-n** (duplication/expression diversity) |
| Dialogue quality | **G-Eval (Liu et al. 2023)** rubric: naturalness, persistence, realism, label consistency (1–5) |
| Label reliability | Independent-sample (36 cases) re-judgment (Claude Sonnet 5) + **Fleiss' κ** agreement (stage 95.9% · technique 95.5% · outcome 100% · intervention point 88.9%); annotation guidelines documented |
| Realism | **AI-detection test** (Jandaghi 2024): iterates the Critic until the synthetic-vs-real detection rate falls |
| Difficulty/ambiguity | **CCDV** (Park et al. 2025): quantifies *ambiguous samples* (attempt-failed, adversarial-normal, etc.) via class-centroid-distance variance (characterizes data difficulty without a detection experiment) |
| Coverage | Reports distribution statistics over T1–T9, persona group, outcome, and channel |

### 8.2 negative (normal, everyday-conversation)

| Dimension | Method |
|---|---|
| Format validation | turns ≥ 4, speaker-label consistency (compound labels separated by `/` allowed), outcome present *(measured: outcome is mostly an empty string)* |
| Signal validation | Code-checks whether `required_ca_signals` (excluding buffer-interval-present) are actually tagged on `psych_technique`, retrying if not *(measured: almost no tagging survives in the final release, though the content the signal was meant to convey appears reflected in the turn text)* |
| Masking | Judged not to constitute personal information since it is based on synthetic personas, so real-name masking was not applied (see §4.2). Only some fields, e.g. addresses, are selectively masked |
| **Structural/rhythmic naturalness** | Address-term consistency, transition markers, reaction-token diversity, buffer phrases/repair, redundant repetition — reviewed with a Claude Sonnet 5–based, narration-first QC prompt |
| **Referential consistency** | Detects information (names, places, etc.) appearing without prior basis — corrected with priority over style items since it is a logical error |
| **Generation artifacts** | Separately flags pure bug-type defects such as a speaker label incorrectly appearing in the `text` field |
| Reproducibility | Already-processed IDs are automatically skipped → safe to re-run/resume chunks after interruption. The QC stage is likewise structured to resume from `submit`/`status`/`fetch` state files |

> The methodological difference for negative (a) is that it uses rule-based verification
> (format, masking) plus retries and a 3-axis LLM-based QC scheme, instead of the positive
> side's Self-BLEU · G-Eval · Fleiss' κ · CCDV.

## 9. Benchmark Task Definitions

1. **Task 1 — Phishing detection** — conversation → {phishing, legitimate}
2. **Task 2 — Type classification** — conversation → T1–T9 (multi-label)
3. **Task 3 — Stage/technique sequence labeling** — utterance sequence → (stage, technique)
   sequence
4. **Task 4 — Defensive intervention-point detection** — identifying `intervention_point`
   (immediately before a transfer/app installation/verification code) and the defensive
   agent's block success rate

> The dataset's contribution is the benchmark itself; detector training/performance reporting
> is separated out as follow-up work. (A minimal baseline table may be attached as an appendix
> if a venue requires it.)

## 10. Anticipated Objections and Responses (Review Preparedness)

| Anticipated objection | This methodology's response |
|---|---|
| "Isn't synthetic data different from the real distribution?" | **Dual grounding** (real FSS phishing anchors + real AIHub normal calls) + iterating the Critic via an **AI-detection test** (Jandaghi) until the human-vs-synthetic discrimination rate drops |
| "Isn't an AI-to-AI conversation meaningless since it would just refuse immediately?" | The victim agent has **meta-awareness blocking** (unaware it is phishing) + natural resistance from persona suspicion tendency. **Refusal is not invalid — it is labeled `outcome=terminated_early`** |
| "Can the labels be trusted?" | **Generation/annotation separation** + annotation guidelines + reported **Fleiss' κ** agreement |
| "Aren't the stage/technique labels arbitrary?" | Stage = Cornish's crime script; technique = **anchored in the established frameworks** of Cialdini, Stajano-Wilson, and Ferreira |
| "Ethics/misuse" | **Text-only, fully synthetic, de-identified**, no deployable voice-attack pipeline. Clearly distinguished from attack-feasibility research (§12) |
| "Isn't the negative (normal) class skewed toward business calls (call centers), making the hard negatives weak?" | A separate negative (a) everyday-conversation subset was built to secure contrastive pairs for T4 (family/acquaintance impersonation) that share the same surface story but differ in structure (§1.2, §2.2) |

## 11. Ethics and Documentation

- **Fully synthetic**: no real victim information or real calls used. Real phishing content is
  grounded only in publicly released (FSS) transcript text; videos are not redistributed.
- **De-identified**: real bank/institution names and numbers are anonymized. Forged documents
  are described only in text.
- **negative (a) masking decision**: the ● masking convention used by the real call-center data
  (`normal_conversations.json`) that subset (b) follows was reviewed as a candidate principle,
  but because negative (a) is entirely generated from synthetic personas rather than real
  individuals, we judged it does not constitute personal information and deliberately did not
  apply real-name masking (only some fields, e.g. addresses, are selectively masked).
- **Restricted intended use**: for detection/defense research only. No deployable voice-attack
  pipeline (text only). → Clearly distinguished from *attack-feasibility* research such as
  ViKing (AsiaCCS 2025) and Heiding & Lermen (2025).
- **Datasheet**: documented per Gebru et al. (2021) covering motivation/composition/
  collection/uses/limitations.
